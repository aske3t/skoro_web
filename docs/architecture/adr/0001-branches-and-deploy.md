# ADR-0001: Ветки и деплой

- **Статус:** принято, 2026-10-02
- **Закрывает:** P-01

## Контекст

- **Живой сайт skorouvas.cz собран из `ec05ede` — вершины `variant1`.** Архитектор проверил это по сайту: кнопки Sign in и Ship now → `/signup` есть только в Navbar этой ревизии.
- **`variant1` целиком входит в `dev`.** `master` (`df9591e`) — первый демо-скелет, отстаёт от `dev` на 13 коммитов и в работе не участвует. При этом GitHub считает `master` веткой по умолчанию (`origin/HEAD → master`).
- **Механизм деплоя неизвестен.** Три коммита «vercel deploy» указывают на ручной `vercel deploy` из CLI. Подключение Git-интеграции не подтверждено.
- **Рабочие ветки живут только локально.** `feature/contact-form` не запушена, и её существование держится на одной машине.

## Решение

1. **`main`** — единственная продовая ветка и Production Branch в Vercel. Создаётся от `ec05ede`, на ту же ревизию ставится тег `prod-2026-05-17`. `main` становится веткой по умолчанию на GitHub.
2. **`dev`** — интеграционная ветка. Vercel собирает её как Preview.
3. **Рабочие ветки** `feature/*`, `fix/*`, `chore/*` создаются от `dev` и пушатся сразу. В `dev` попадают через PR. Когда появится CI (TASK-002), его прохождение станет обязательным условием merge.
4. **Релиз `dev → main`** — через PR и **только по явной команде владельца**.
5. **Hotfix:** `hotfix/*` от `main` → PR в `main` → затем `main` вливается в `dev`.
6. **Деплой только через Git-интеграцию Vercel.** `vercel deploy --prod` с локальной машины не используется: прод должен однозначно соответствовать коммиту в `main`.
7. **`master` и `variant1` удаляются** после выполнения пп. 1–2 и проверки настроек Vercel.

## Последствия

- **Плюсы.** Прод воспроизводим, его состояние видно по ветке. Preview на каждую ветку даёт ссылку для ручной проверки.
- **Минусы.** Нужна разовая настройка Vercel и GitHub (ниже).

## Действия владельца

- **Vercel → Settings → Git:** репозиторий подключён, Production Branch = `main`.
- **Vercel → Settings → Environment Variables:** разнести значения по Production и Preview.
- **Vercel → Settings → General:** Node.js Version = 22.x.
- **GitHub:**
  - Default branch = `main`;
  - для `dev` и `main` включить защиту: merge только через PR, а после TASK-002 — с зелёным CI.

## Отклонённые варианты

- **Оставить `variant1` продовой.** Имя не отражает роль, и путь изменений до прода остаётся неочевидным.
- **Сделать продовой `master`.** Пришлось бы перезаписывать историю устаревшей ветки. Создать `main` чище.
