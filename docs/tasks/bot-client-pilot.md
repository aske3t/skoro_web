# Пилот: клиентский интерфейс в Telegram-боте

> Решения — [ADR-0006](../architecture/adr/0006-client-options-and-bot-orders.md) (главный документ), ADR-0005 (статусы и кнопки, §4), ADR-0003, ADR-0002 (дополнение: миграции совместимы с `main`), ADR-0004.
> Ветка: `feature/bot-clients` от `dev`. Работа итеративная: перед шагом — план без кода и «ок» владельца, после шага — проверка владельцем в dev-боте и коммит.
> Живое описание бота — `docs/telegram-bot.md`, обновлять после каждого шага. Отступления от ADR и вопросы — в PROPOSALS.
> **Пилот:** два клиента, данные вносит владелец SQL-сниппетами, одна общая опция «Доставка по городу» (`city_delivery`). Клиенты входят в бот по ссылке-приглашению (ADR-0006 §5). Регистрации в пилоте нет.

## Шаг 0 — подготовка окружения

**Агент** пишет `docs/ops/telegram-dev.md` — инструкцию для владельца. Сначала сверь её с актуальной документацией Vercel и Telegram.

**⏸ Владелец по инструкции:**
1. **Dev-бот** через @BotFather. Тестовая группа «Skoro · Заявки DEV» с этим ботом, её ID.
2. **Vercel → Deployment Protection → Protection Bypass for Automation** — секрет.
3. **Vercel → Environment Variables → Preview:**
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET` — dev-бота;
   - `TELEGRAM_ADMIN_IDS` — как в проде;
   - `APP_URL` — стабильный адрес ветки `feature/bot-clients` с параметром обхода защиты.

   В Production: `APP_URL=https://skorouvas.cz`. Те же dev-значения — в `.env.local`.
4. **Вебхук dev-бота** — на адрес ветки с параметром обхода. Скрипт `bot:webhook` научить брать адрес из `APP_URL`.

**Проверка:** `/start` в dev-боте получает ответ с Preview, `getWebhookInfo` без ошибок. Боевой бот не тронут.

## Шаг 1 — данные и чистые модули

**1.1. Диагностика** (только `select`):

```sql
select version();
select slug, label, base_price, max_lead_minutes from public.delivery_slots order by display_order;
select payment_status, count(*) from public.orders group by 1;
```

**1.2. Миграция `<ts>_client_options.sql`** — только расширение. Состав — ADR-0006:

| Что | По ADR-0006 |
|---|---|
| `clients`, `client_contacts` (с `invite_token_hash`, `invite_expires_at`), `client_locations`, `telegram_users`, `service_options` (+ строка `city_delivery`, `form_kind = city_delivery`), `client_options` (+ триггер: уникальная опция — только своему клиенту), `notifications` | §1, §5 |
| `bot_sessions (key text primary key, value jsonb not null, updated_at timestamptz)` — хранилище `session()` grammY | §4 |
| `orders`: колонки `client_id`, `client_option_id`, `contact_id`, `created_via` (`bot` / `web` / `admin`), `form_data jsonb`, `price_breakdown jsonb`, `tariff_kind`, `number` (своя последовательность, со сквозной нумерацией старых строк, как `leads.number`), `accepted_at`, `cancelled_at`, `cancelled_by`, `handled_by_tg_id`, `handled_by_name`, `tg_chat_id`, `tg_message_id`; `user_id` — снять `not null`; default `payment_status` → `'pending_payment'` + `check` по значениям из диагностики | §6 |
| `public.create_option_order(...)` — `security definer`, `search_path = ''`, `execute` только у `service_role`; проверки «контакт и клиент активны, опция принадлежит клиенту и активна» с кодами-исключениями | §6 |
| `leads.delivery_at timestamptz null` | §7 |

У всех новых таблиц RLS включён, политик нет, `revoke all` у `anon` и `authenticated`. Для каждого изменения существующих объектов — `git grep … origin/main -- src` и вывод в отчёт.

**1.3. Чистые модули с тестами:**
- **`lib/orders/prague-time.ts`** — `datetime-local` → момент времени по Праге. Тесты DST: 2026-03-29, 2026-10-25.
- **`lib/orders/slot.ts`** — выбор слота по пражским минутам; режим «как можно скорее» → самый срочный слот. Старый `lib/calculator/slotpicker.ts` удаляется, когда его перестанет использовать старая форма кабинета; до тех пор — не трогать.
- **`lib/pricing/tariffs/`** — реестр, `slot_table`, `flat`, zod параметров, код `tariff_invalid`.
- **`lib/options/forms/`** — реестр, `city_delivery`. Правила валидации импортируются из `lib/leads`.
- **`lib/telegram/init-data.ts`** — проверка `initData` Mini App. Тест — на данных, подписанных тестовым токеном.
- **`lib/telegram/invite.ts`** — генерация токена, хэш, разбор `start`-параметра `inv_<токен>`, проверка срока. Тесты.

**1.4. `docs/ops/clients.md`** — SQL-сниппеты с подстановками:
- клиент;
- контакт: имя, телефон, email — email нужен для писем о статусах;
- точка;
- подключение `city_delivery` с `slot_table` (пример JSON по slug из диагностики, `byLocation` — необязательно);
- уникальная опция (пример);
- проверочный `select` «что видит клиент».

**⏸ Владелец:**
- применяет миграцию: `db push --db-url`;
- заводит двух пилотных клиентов **с разными тарифами** «Доставки по городу». Для теста контактом клиента 1 можно указать себя — приглашение потом откроешь со своего Telegram;
- агент перегенерирует типы и проверяет данные `select`-ами.

## Шаг 2 — время доставки в форме на сайте

- **`ContactForm`, блок доставки:** поле «Когда доставить» — «Как можно скорее» (по умолчанию) или «Ко времени» с `datetime-local`. Под полем — подсказка слота. Стиль формы не меняется.
- **Сервер:** zod → `leads.delivery_at` (null = как можно скорее), время по Праге.
- **Показ:** в сообщении Telegram и в письме о взятии в работу. Тесты.

## Шаг 3 — роли, приглашения и меню в боте

- **Каждое личное обновление** → upsert `telegram_users`.
- **Роль на каждое обновление:** админ (`TELEGRAM_ADMIN_IDS`), клиент (активный `client_contacts.telegram_user_id`), гость.
- **Хранилище:** встроенный `session()` grammY с адаптером на `bot_sessions`. Плагины не подключать.
- **`/invite`** (только админ, в личке), по ADR-0006 §5:
  - список активных контактов без Telegram — кнопками;
  - выбор → ссылка `https://t.me/<бот>?start=inv_<токен>`, срок 7 дней;
  - у привязанных контактов — кнопка «Отвязать».
- **`/start inv_<токен>`:**
  - условная привязка, токен стирается;
  - клиенту — приветствие с названием клиента;
  - в группу «Заявки» — «<контакт> (<клиент>) подключил Telegram: @username»;
  - ошибки — по ADR-0006 §5.
- **`/logout`** — клиент отвязывает себя сам.
- **Меню (reply-клавиатура):**
  - гость: «Как подключиться» (текст: попросите ссылку у менеджера) и «Связаться»;
  - клиент: «🆕 Новый заказ», «📋 Мои заказы», «👤 Профиль», «☎️ Связаться».

  Админ в личке — как сейчас, плюс `/invite`.
- **`bot:commands`** — команды по ролям (scope).

## Шаг 4 — заказ через Mini App

- **Каркас `/tg/*`:**
  - layout со скриптом `telegram-web-app.js`;
  - тема из Telegram;
  - передача `initData` в Server Action;
  - свои минимальные типы WebApp, без пакетов;
  - страницы `noindex`;
  - открытие вне Telegram → «Откройте через бота».
- **«Новый заказ»** → активные опции клиента кнопками `web_app` на `/tg/order/<clientOptionId>`. Если опция одна — сразу форма.
- **Форма** по `form_kind` с `form_defaults`: `city_delivery` на `AddressInput`, `PhoneInput`, `PhotoField`.
- **Превью цены** — тем же тарифом. Клиенту видны только его цены.
- **Перед отправкой — сводка.**
- **`submitOptionOrder`** — ADR-0006 §6.
  - Коды ошибок: `unauthorized`, `not_linked`, `client_inactive`, `option_unavailable`, `validation` (+ `fieldErrors`), `invalid_time`, `slot_past`, `slot_outside_hours`, `tariff_invalid`, `server_error`.
  - При ошибке введённые значения сохраняются.
- **После записи** (`after()`):
  - в группу «Заявки» — сообщение заказа с кнопками «✅ Принять / ❌ Отклонить», `tg_chat_id` и `tg_message_id` сохраняются;
  - клиенту в чат — «Заказ №N получен»;
  - Mini App показывает экран успеха и закрывается.
- **«📋 Мои заказы»** — последние 10 заказов клиента: номер, опция, когда, статус, цена.

## Шаг 5 — статусы и уведомления клиенту

- **Кнопки заказа** (ADR-0005 §4), только админы, условные переходы, сообщение пересобирается из БД:

  | Кнопка | Переход |
  |---|---|
  | `accept` | `new → in_progress` |
  | `decline` | `new → cancelled` |
  | `deliver` | `in_progress → delivered` |
  | `cancel` | `in_progress → cancelled` |
- **Уведомления клиенту** при «принят», «доставлен» и «отменён»: в бот и на email контакта (Resend, язык — как у существующих писем, P-29). Каждая пара «событие + канал» — строка `notifications`. При сбое у админа появляется кнопка повтора.
- **Заявки с сайта:** у взятой заявки на доставку — кнопка «📦 Доставлено» → `leads.status = done` → письмо «Доставка выполнена» через `notifications`. Письмо о взятии в работу не трогать.

## Ограничения

- **Источник решений — ADR-0006.** Отступление — только через PROPOSALS.
- **Миграции** — только расширение, применяет владелец. **Данных клиентов нет ни в миграциях, ни в репозитории**: он публичный.
- **Новые npm-зависимости не нужны:** `grammy` уже есть, скрипт Telegram WebApp подключается тегом `<script>`.
- **Не трогать:**
  - калькулятор;
  - лендинг — кроме поля времени (шаг 2) и скрытия плейсхолдеров (шаг 6);
  - старые страницы кабинета (TASK-005 отложена);
  - поведение существующих кнопок заявок — кроме новой «Доставлено».
- **Юридические тексты не писать.** Тексты сообщений бота и писем — черновики для утверждения владельцем.
- **Перед «готово» на каждом шаге:** `tsc`, `lint`, `test`, `build`. Тесты обязательны для всех чистых модулей шага 1 и для разбора `callback_data`.

## Приёмка пилота

- [ ] **Вход:** `/invite` → ссылка → контакт клиента 1 открывает её и видит название клиента; в группе — сообщение о подключении.
- [ ] **Ссылка:** повторное открытие той же ссылки (или с другого аккаунта) → «Ссылка недействительна». После «Отвязать» и нового приглашения вход снова работает.
- [ ] **Гость:** без приглашения бот показывает только «Как подключиться» и «Связаться».
- [ ] **Заказ:** клиент открывает форму «Доставки по городу», видит свою цену — у двух клиентов разную на одном слоте — и оформляет заказ. Заказ приходит в группу с кнопками, клиенту — подтверждение.
- [ ] **Статусы:** «Принять» → клиенту сообщение и письмо «принят». «Доставлен» → «доставка выполнена». «Отклонить» → «отменён».
- [ ] **Время:** «как можно скорее» → экспресс-цена; время через 5 часов → цена «в течение дня»; время в прошлом или вне рабочих часов → понятная ошибка.
- [ ] **Сайт:** поле времени работает, время видно в Telegram. Кнопка «Доставлено» у заявки → письмо.
- [ ] **Тариф:** битый `tariff_params` в БД → клиенту понятная ошибка, админу — сообщение.
- [ ] **Безопасность:** запрос в Server Action без `initData` или с подделанным → `unauthorized`.
- [ ] **Окружения:** dev-бот и боевой бот не мешают друг другу.
