# Старт: пилот клиентского бота — что прочитать и как работать

> Для агента, который ведёт пилот. Сама задача — [bot-client-pilot.md](bot-client-pilot.md), решения — [ADR-0006](../architecture/adr/0006-client-options-and-bot-orders.md). Этот файл их не заменяет: здесь контекст, порядок чтения и правила работы в этом репозитории. Составлен 2026-11-02.

## 1. Твоя зона

- **Твоё:** пилот клиентского интерфейса в Telegram-боте — шаги 0–6 из `bot-client-pilot.md`.
- **Не твоё:** веб-кабинет `/dashboard/*` и `src/components/account/`. Его ведёт другой агент (TASK-005 отложена и будет переписана поверх ADR-0006). Калькулятор и лендинг тоже не трогать — кроме шага 2 (поле времени в `ContactForm`) и шага 6 (скрыть плейсхолдеры).
- **Общее с кабинетом:** `lib/orders/`, `lib/options/forms/`, `lib/pricing/tariffs/`, функцию `create_option_order`. Кабинет потом вызовет их с `created_via = 'web'`, поэтому домен не должен зависеть от Telegram. Проверка `initData` живёт только в слое Mini App (`lib/telegram/init-data.ts` и action в `src/app/tg/`). Домен получает уже проверенные контакт и клиента.

## 5. Правила работы

- **Отдельный рабочий каталог.** В одном checkout работают владелец и второй агент и переключают ветки. Работай в git worktree:
  ```bash
  git fetch origin && git worktree add ../skoro-bot -b feature/bot-clients origin/dev
  ```
  Перед каждым коммитом проверяй ветку. В `dev` и `main` не коммитить никогда.
- **Итеративно:** план шага без кода → «ок» владельца → код → `npx tsc --noEmit`, `npm run lint`, `npm test`, `npm run build` → проверка владельцем в dev-боте → коммит.
- **БД:**
  - доступа к ней у тебя нет. Диагностические `select` пишешь ты, выполняет владелец в SQL Editor и присылает результат;
  - миграции не применять (`db push`, `db reset`, `migration up`) — их применяет владелец.
- **Секреты:** не выводить и не коммитить; `.env.local` не трогать, значения вписывает владелец. Репозиторий публичный: данных клиентов нет ни в миграциях, ни в сниппетах, только подстановки.
- **Зависимости:** новых npm-пакетов не добавлять; WebApp-скрипт Telegram подключается тегом `<script>`.
- **Тексты:**
  - для пользователя — на русском, в компонентах и сообщениях; сервер возвращает коды ошибок;
  - юридических текстов не писать; сообщения бота и письма — черновики для утверждения владельцем.
- **Проверка в браузере** через Chrome DevTools (CDP) — только с разрешения владельца.
- **Общение:** владелец пишет по-русски и просит отвечать коротко. Долгие расследования старых проблем — только с его согласия: находку записать в PROPOSALS и спросить.
- **Конец сессии:** `/handoff` (STATE и PROPOSALS), плюс `docs/telegram-bot.md` после каждого шага.
