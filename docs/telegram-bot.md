# Telegram-боты Skoro

> Живой документ: обновляется после каждого шага. Ведёт агент.
> Решения — [ADR-0006](architecture/adr/0006-client-options-and-bot-orders.md) (§4 — два бота, §8 — окружения), план — [пилот](tasks/bot-client-pilot.md). При противоречии с кодом — вопрос в [PROPOSALS.md](architecture/PROPOSALS.md).

## Что это

Два бота, общие сервер и БД (P-43). Сообщениями в Telegram они не обмениваются: связь — через БД и серверный код.

| | Служебный (нынешний) | Клиентский (новый) |
|---|---|---|
| Кто | админы; позже курьеры | клиенты и гости |
| Где | группа «Заявки» и личка админа | только личка; добавление в группы выключено |
| Что делает | уведомления о заявках с кнопками (`src/lib/leads/notify.ts`), команды, `/invite`; по плану пилота — карточки заказов | вход по приглашению, меню, профиль, `/logout`; по плану пилота — Mini App, «Мои заказы», статусы клиенту |
| Вебхук | `POST /api/telegram/dispatch` | `POST /api/telegram/client` |
| Код | `src/lib/telegram/` | `src/lib/telegram/client/` |
| Статус | работает | **[Факт]** работает на dev-боте. Заказы и статусы — шаги 4–5 пилота |

Нажатие кнопки получает только бот, который отправил сообщение, и только он может это сообщение править. Поэтому карточку заказа шлёт и обрабатывает служебный бот, а клиенту пишет клиентский.

Оба бота живут внутри Next.js, без отдельного процесса и сервера. Входящие обновления обрабатывает
Route Handler (runtime `nodejs`), вызывая grammY `webhookCallback`.

**Важно про импорты.** Скрипты `bot:dev`/`bot:commands` запускаются как обычный `node`, без
бандлера Next.js — он не умеет резолвить алиас `@/*` и расширения `.ts` автоматически. Поэтому
внутри `src/lib/telegram/**` относительные импорты между файлами модуля пишутся с явным
расширением (`"./commands.ts"`), а не через алиас `@/...`. Это разрешено флагом
`allowImportingTsExtensions` в `tsconfig.json` (безопасно, так как `noEmit: true`). Route handler
собирается Next.js и может использовать `@/lib/telegram/bot` как обычно.

## Клиентский бот: вход и меню

Вход только по приглашению (ADR-0006 §5). Админ в служебном боте получает ссылку `t.me/<клиентский бот>?start=inv_<токен>` и пересылает клиенту. Токен одноразовый, живёт 7 дней, в БД только SHA-256, новая ссылка отменяет прежнюю.

| Кто | Меню |
|---|---|
| Гость | «Как подключиться», «Связаться» |
| Клиент (активный контакт активного клиента) | «🆕 Новый заказ», «📋 Мои заказы» (пока «Появится на следующем шаге»), «👤 Профиль», «☎️ Связаться» |

- **Отказ:** просроченная, использованная, чужая ссылка или Telegram, уже привязанный к другому контакту, — один текст: «Ссылка недействительна — попросите менеджера прислать новую». Причина наружу не раскрывается.
- **При входе** служебный бот пишет в группу «<контакт> (<клиент>) подключил Telegram: @username». Сбой этого сообщения вход не отменяет.
- **Смена аккаунта:** `/logout` у клиента или «Отвязать» в `/invite`, затем новая ссылка.
- **Группы:** сообщения игнорируются, даже если бота добавили.
- **Команды в меню:** `npm run bot:commands -- --bot client`.

## Mini App

Форма заказа — страница сайта `/tg/order/<clientOptionId>`, которую Telegram открывает внутри чата (ADR-0006 §4).

- **Открытие:** «🆕 Новый заказ» в клиентском боте присылает inline-кнопку `web_app` на каждую опцию клиента. Кнопка reply-клавиатуры не подходит, у неё пустой `initData`. Сам бот открыть Mini App не может, поэтому даже одна опция приходит кнопкой.
- **Адрес** строится из `APP_URL` со всеми его параметрами (`buildAppUrl`). На Preview это секрет обхода и `x-vercel-set-bypass-cookie=samesitenone`: Vercel ставит cookie, без которого Server Actions страницы упрутся в защиту. Секрет обхода виден в кнопках dev-бота; на проде `APP_URL` без параметров.
- **Вход:** страница передаёт `initData` в Server Action (`src/app/tg/actions.ts`). Проверяются подпись токеном клиентского бота и свежесть (24 часа), затем активный контакт активного клиента и его опция. Supabase-сессия не нужна.
- **Layout** свой, корневой (`src/app/tg/layout.tsx`, P-47): `lang="ru"`, цвета темы Telegram, `noindex`, без шапки, футера и шрифтов сайта. Скрипт Telegram подключается тегом через `next/script`, своих типов WebApp — минимум (`src/components/tg/telegram-web-app.ts`).
- **Вне Telegram** страница пишет «Откройте форму через бота Skoro в Telegram».

## Кнопки под заявкой

Уведомление о заявке с сайта уходит в группу (`TELEGRAM_CHAT_ID`). В заголовке указан тип: «Доставка» или «Вопрос». Для доставки в сообщении есть адрес забора, адрес доставки, телефон получателя и способ оплаты; фото, если оно приложено, приходит следующим сообщением — ответом на заявку (`sendPhoto`, `file_id` не сохраняется). Две кнопки есть **только у заявок на доставку** (`kind = delivery`); вопросы приходят без кнопок.

| Кнопка | `callback_data` | `leads.status` | Кто |
|---|---|---|---|
| ✅ Взял в работу | `lead:take:<uuid>` | `in_progress` | только админ |
| 🚫 Спам | `lead:spam:<uuid>` | `spam` | только админ |

Сценарий:
1. Нажимает админ (`TELEGRAM_ADMIN_IDS`), заявка в статусе `new` → пишутся `status`, `handled_by_tg_id`, `handled_by_name`, `handled_at`; сообщение пересобирается из БД, внизу строка «✅ Взял в работу: Имя · дата, время» (Europe/Prague), кнопки убираются.
2. Нажимает не админ → всплывающее окно «доступно только администраторам», ничего не меняется.
3. Заявка уже не `new` (повторное нажатие, второй админ, повтор update от Telegram) → всплывающее окно «уже обработал(а): Имя», ничего не меняется.
4. Заявки, отправленные до этого шага, кнопок не имеют.

Идемпотентность — условный `update … where status = 'new'`, состояния в памяти нет.
На каждый `callback_query` вызывается `answerCallbackQuery`. Права проверяются на каждое нажатие: кнопку в группе видит любой участник.

Миграция: `20261014103738_leads_handled_by.sql` (nullable-колонки в `leads`).

## Переменные окружения

| Переменная | Где читается | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | `bot.ts`, `notify.ts` | токен служебного бота: уведомления о заявках и приём обновлений |
| `TELEGRAM_CHAT_ID` | `notify.ts` | группа «Заявки» |
| `TELEGRAM_WEBHOOK_SECRET` | `dispatch/route.ts` | секрет служебного бота для `X-Telegram-Bot-Api-Secret-Token`; при установке вебхука передаётся в `setWebhook` |
| `TELEGRAM_CLIENT_BOT_TOKEN` | `client/bot.ts` | токен клиентского бота |
| `TELEGRAM_CLIENT_WEBHOOK_SECRET` | `client/route.ts` | секрет клиентского бота; вебхук с секретом другого бота получает 401 |
| `TELEGRAM_CLIENT_BOT_USERNAME` | с шага 3 | имя клиентского бота для ссылок-приглашений |
| `APP_URL` | `scripts/telegram-set-webhook.mts`, с шага 4 — кнопки Mini App | адрес сайта; на Preview — с параметрами обхода защиты (ADR-0006 §8) |
| `RESEND_API_KEY` | `email/resend.ts` | ключ Resend (Sending access, домен `notify.skorouvas.cz`) |
| `EMAIL_FROM` | `email/resend.ts` | `SKORO u vás <noreply@notify.skorouvas.cz>` |
| `EMAIL_REPLY_TO` | `email/resend.ts` | `skorodelivery@gmail.com` — куда приходят ответы клиентов |
| `TELEGRAM_ADMIN_IDS` | `permissions.ts` | Telegram user id админов через запятую; кто может нажимать кнопки. Свой id — у @userinfobot или в `from.id` ответа `getUpdates` |

Читаются лениво, без `NEXT_PUBLIC_`. В Vercel: Production — боевые значения, Preview — значения
dev-ботов (ADR-0006 §8). Клиентские переменные в Production заводятся на шаге 6. В документы и
коммиты секреты не попадают.

## Локальная разработка (long polling)

```bash
npm run bot:dev
```

Для проверки кнопок запустите **два процесса**: `npm run dev` (сайт, отправляет заявку) и
`npm run bot:dev` (принимает нажатия). Polling слушает `message` и `callback_query`.

Скрипт сначала проверяет `getWebhookInfo()`: если на боте уже стоит вебхук — откажется
стартовать (polling снял бы вебхук и перехватил обновления у развёрнутого сайта). Для разработки
по ADR-0006 §8 заводятся два dev-бота, их значения лежат в `.env.local`
(настройка — [docs/ops/telegram-dev.md](ops/telegram-dev.md)). Скрипты `bot:dev`, `bot:commands` и
`bot:webhook` принимают `-- --bot service` или `-- --bot client`; без параметра — служебный бот.

Обновить меню команд в Telegram (`/`):

```bash
npm run bot:commands
```

## Вебхуки

Боевые боты — на `skorouvas.cz`, dev-боты — на стабильный адрес ветки (ADR-0006 §8). Защиту Preview
Telegram проходит через Protection Bypass for Automation: секрет передаётся параметром адреса.

`npm run bot:webhook` (`scripts/telegram-set-webhook.mts`) ставит вебхук с `secret_token` и
`allowed_updates: message, callback_query`, сбрасывает накопившиеся обновления и печатает состояние вебхука.

| Бот | Параметр | Маршрут | Секрет |
|---|---|---|---|
| служебный | без параметра или `-- --bot service` | `/api/telegram/dispatch` | `TELEGRAM_WEBHOOK_SECRET` |
| клиентский | `-- --bot client` | `/api/telegram/client` | `TELEGRAM_CLIENT_WEBHOOK_SECRET` |

- **Адрес** берётся из `APP_URL`, без него — ошибка. Из параметров в адрес вебхука попадает только
  `x-vercel-protection-bypass`: `x-vercel-set-bypass-cookie` отвечает редиректом.
- **`-- --info`** только читает: бот, адрес, очередь, последняя ошибка. Запускать первым, чтобы убедиться, чей токен в `.env.local`.
- **`-- --delete`** снимает вебхук; после этого снова работает `bot:dev`.
- **Защита боевого бота:** если вебхук стоит на `skorouvas.cz`, а команда уводит его оттуда или снимает, скрипт откажет. Осознанно — `--force`.
- **Секреты:** значения параметров в выводе маскируются. Переменная окружения важнее `.env.local`. Секрет должен совпадать со значением в Vercel, иначе маршрут отвечает 401.
- Пока вебхук стоит, `bot:dev` откажется стартовать — так задумано.

## История шагов

- **Шаг 1 (2026-10-14).** Каркас: `grammy`, `bot.ts`, route handler с проверкой секрета,
  `bot:dev`/`bot:commands`, команды `/start`, `/help`, `/orders`. Без БД, без прав — они появятся
  в шаге 2 (кнопки под заявкой) и шаге 3 (регистрация курьеров).
- **Шаг 2 (2026-10-15).** Кнопки «Взял в работу» / «Спам» под заявкой, только для админов.
  Миграция `leads_handled_by`, `escapeHtml` вынесен в `src/lib/html.ts`, `formatLeadMessage`
  принимает необязательную `note`. Тесты: `callback_data`, права, форматирование.
- **Форма доставки (2026-10-16).** Поля: адрес забора и доставки (обязательно), телефон
  клиента (для доставки обязателен), телефон получателя (необязательно), способ оплаты
  «Наличные» / «Оплата на сайте» (обязательно; онлайн-оплаты нет, это только отметка до TASK-006),
  фото отправления (необязательно, JPG/PNG/WebP до 4 МБ, тип по байтам, уходит в Telegram через
  `sendPhoto`). Миграция `20261016122134_leads_delivery_details`. В `next.config.ts` лимит
  Server Actions поднят до 5 МБ. Письмо клиенту о принятии заявки — следующий шаг (P-29).
- **Фото: буфер обмена и мобильные (2026-10-20).** `PhotoField`: выбор из галереи или камеры
  (без `capture`), перетаскивание, вставка Cmd/Ctrl+V в любом месте формы. В браузере фото
  уменьшается до 2048 px по длинной стороне и перекодируется в JPEG 0,85 (`photo-client.ts`,
  canvas, без зависимостей); EXIF, включая GPS, отбрасывается. Исходник — до 20 МБ, на сервер
  уходит до 4 МБ. Пока фото обрабатывается, отправка заблокирована. Без JS — обычный файл до 4 МБ.
- **Письмо клиенту (2026-10-21).** При «✅ Взял в работу» у заявки на доставку бот отправляет
  клиенту письмо через Resend (`src/lib/email/`, HTTP API без SDK): «objednávka č. XXXXXXXX
  převzal kurýr», краткое описание доставки, телефон поддержки. Только чешский: языковых версий
  сайта пока нет; новые языки — в `TEMPLATES` (`lead-taken.ts`). Номер — первые 8 символов uuid.
  Под заявкой в группе появляется «📧 Письмо клиенту отправлено» или «⚠️ … не отправлено».
  Повтор исключён условным update и `Idempotency-Key: lead-taken/<id>`. Сбой письма не откатывает
  статус. Отправка с субдомена `notify.skorouvas.cz` (DKIM/SPF в Resend), ответы — на Gmail (P-29).
- **Номер заявки и оформление письма (2026-10-21).** Миграция `20261020235139_leads_number`:
  порядковый `leads.number` с 0 (nullable-колонка + последовательность `leads_number_seq`;
  identity не подходит — она всегда NOT NULL, а ADR-0002 разрешает только nullable). Старые заявки
  пронумерованы по `created_at`. Номер — в заголовке Telegram («Новая заявка №12 · Доставка»)
  и в письме. Письмо — тёмная карточка в цветах сайта (`#1f1526`, акцент `#b895ff`), кнопка
  «Zavolat», логотип внизу. Логотип встроен в письмо inline-вложением (`cid:skoro-logo`,
  `src/lib/email/logo.ts`, PNG 440 px из `public/images/home/skoro_cropped.png`), поэтому
  не зависит от прода.
- **Надёжность письма (2026-10-21, P-30).** `leads.client_notified_at` (миграция
  `20261021005207`) хранит факт отправки. Если письмо не ушло — под заявкой «⚠️ Письмо клиенту
  не отправлено» и кнопка «📧 Отправить письмо повторно» (`lead:email:<uuid>`, только админы).
  Повторное нажатие «Взял в работу» на взятую заявку без письма тоже досылает его. Ответ на
  устаревшее нажатие (бот был выключен) больше не прерывает обработку; `bot.catch` не даёт
  ошибке остановить бота.
- **Два бота (2026-11-05, P-43).** Решение владельца, ADR-0006 §4 изменён: клиентский интерфейс —
